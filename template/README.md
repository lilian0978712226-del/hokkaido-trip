# 旅遊網站模板（從「北海道雪日記」整理）

這個資料夾可以把任何一趟旅行做成和北海道網站一樣的單頁網站。
**原則：`src/` 是共用模板，不要為了某一趟旅行改它；每趟旅行的東西都放在 `trips/<旅行代號>/`。**
旅行資料夾裡放一個和 `src/` 同名的檔案，就會蓋掉模板的那一個（例如 `trips/kyoto-2027/v8.js`）。

```
template/
  make.py              ← 建置：python3 template/make.py template/trips/<代號> [輸出資料夾]
  verify.py            ← 檢查：python3 template/verify.py <輸出資料夾>/index.html
  src/                 ← 共用模板（建置腳本、樣式、功能）
  assets/              ← 預設 App 圖示、manifest、離線快取 sw.js
  trips/hokkaido-2027/ ← 範例：北海道（就是目前上線的網站）
```

## 一、開一趟新旅行（照順序）

1. `cp -r template/trips/hokkaido-2027 template/trips/<代號>`（代號例：`kyoto-2027`）。
2. 改 `trip.json`：
   - `id`：代號。
   - `storage_prefix`：**新旅行一定要填**（例：`"kyoto-2027"`）。同一個 github.io 網址底下的網站共用手機儲存空間，沒填的話記帳、打勾會和北海道混在一起。只有北海道是空字串（保留舊資料）。
   - `publish_path`：發布到 repo 的哪個資料夾，例：`"kyoto"` → 網址 `https://<帳號>.github.io/hokkaido-trip/kyoto/`。
   - `loose`: `true`（基底頁換過內容時，找不到的裝飾修補會跳過並印出 WARN，而不是直接失敗）。
3. 改 `data.js`（行程主資料，見下方「資料格式」）。
4. 改 `orig.html`（基底頁）：標題、出發日期、航班、住宿、租車、出發前待辦、行李清單、入境與退稅說明等文字。日期／航班字串如果改了，`src/build.py` 裡對應的 `rep()` 修補會找不到 → 把 `build.py` 複製進旅行資料夾，改成新字串。
5. 依照下面的「地區專屬清單」，把需要換的檔案複製進旅行資料夾再改。
6. 上網查證：營業時間、點燈或活動日期、緊急電話、日落地點。查不到的就標「以官網為準」，不要自己編。
7. `python3 template/make.py template/trips/<代號>` → `python3 template/verify.py <輸出>/index.html`。
8. 用 Playwright 在 390px 寬截圖檢查（首頁、每天行程、記帳、地圖），沒問題才推上 GitHub。

## 二、資料格式（`data.js`）

```js
const days=[{
  "date":"2027-02-10", "label":"札幌・抵達與燒肉", "route":"台中 → 新千歲 → 札幌",
  "theme":"一句話主題", "food":"🥩", "walkLegs":[5,6], "weather":"天氣提示文字",
  "events":[["08:20","地點名稱","說明","🧳"], ...]      // [時間, 名稱, 說明, 圖示]
}, ...];
const userNotes={"0-2":"第 1 天第 3 站的備註（可換行 \n）", ...};   // key = "第幾天-第幾站"，從 0 開始
```
- `walkLegs`：第幾段（到第 N 站那段）是步行，其餘預設開車。
- 站名裡含「Hotel／STAY／飯店」→ 住宿；含「機場／租車」→ 交通；`build2.py` 有美食關鍵字與必去清單（新旅行要換成新店名）。

## 三、地區專屬清單（換地點時要看的地方）

| 檔案 | 位置 | 內容 | 換地點怎麼做 |
|---|---|---|---|
| `orig.html` | 整份 | 基底頁文字、航班、住宿、租車、清單、退稅 | 照新旅行改寫 |
| `build.py` | `rep(...)` 字串 | 品牌名「北海道雪日記」、日期、航班登機證、美食圖鑑標題、住宿卡名稱 | 複製進旅行資料夾改字串 |
| `build2.py` | 美食關鍵字、必去清單、上方導覽、`STARLUX` 字樣 | 標籤判斷用的店名、航空公司 | 複製進旅行資料夾改 |
| `hero.svg` | 首頁插畫 | 北海道風景 | 新地點重畫（同樣的柔和描線風） |
| `extra.js` | `dayArt`、美食街 `keys`、`pick()` | 每天主題小圖、美食街店家與圖示 | 改成新店家 |
| `v2.js` | `NAV` | 中文站名 → 當地語言的 Google 地圖搜尋詞 | 每一站都要有 |
| `v2.js` | `CITY`、`SCENES`、`REG`、`PTS`、`RICH` | 每天天氣城市、每天過場動畫、小地圖位置、特製備註（鱗友朝市招牌照） | 動畫可沿用通用的車／飛機；`RICH` 可清空 |
| `v2.js` | 記帳預設 `b:'陳肥肥'`、`rate:0.21` | 旅伴名字、匯率 | 改名字與當地幣別匯率 |
| `v6.js` | `PH` | 當地語言溝通卡 | 換語言（日本以外要改 `speechSynthesis` 語系） |
| `v6.js` | `HOTELS`、`EM` | 計程車給司機看的飯店名、緊急電話 | 查證後換 |
| `v7.js` | `HOURS` | 營業時間 `[正規式, 開, 關, 顯示文字, (指定第幾天)]` | 查證後換 |
| `v7.js` | `LOC`、`LIGHTS` | 每天日落地點（緯度、經度、名稱）、點燈與末班時間 | 每天一筆，日落永遠排第一 |
| `v8.js` | `C`、`NAME`、`ICON`、`CUSTOM_IC`、`ROADS`、`city()`、`DEF` | 點亮地圖的城市位置、名稱、徽章圖示、小路、站點→城市的判斷 | 依新地點重排 |
| `v8.js` | `LANDPTS`、`HK`、`MT()`／`TREE()` 位置、湖 | 地圖海岸線、右下角全島小地圖、山與樹的位置 | 新地點重畫海岸線；山樹用同一套函式 |
| `assets/` | App 圖示 | 使用者自己的水彩圖示 | 可放進 `trips/<代號>/assets/` 覆蓋 |

不用換、會自動跟著資料走的功能：記帳＋兩支手機合併帳本、行程「⇅ 調整」（上下移、移到別天、改時間、刪除、傳給旅伴同步，`v9.js`）、備份還原／一鍵同步／匯入行事曆／日圓計算機／小日記與回憶卡（`v11.js`）、清單與全部完成動畫、出發倒數、「現在該去哪」、自己新增／改去別家、點亮地圖的星星與存圖分享、下排 D1–D9、離線、日本時區判斷（**時區換地點時要改 `orig.html` 裡的 `japanParts()`**）。

## 四、設計規則（使用者的偏好，做新旅行也要遵守）

- 手機優先（iPhone Safari、390px 寬），不能橫向捲動；支援 `prefers-reduced-motion`。
- 柔和低彩度、圓角、可愛但精緻；線條要淡，不要粗黑框；山不要畫成三角形。
- 不畫任何有版權的角色（例如 Miffy）；吉祥物是原創的雪丸（銀喉長尾山雀）。
- 公開網站不放使用者英文全名。
- 每個行程卡：時間框下面一個分類標籤（美食／住宿／交通／景點／逛街／停車），必去用時間框右上角的金星；按鈕順序固定「導航・複製・完成」，備註在下一排。
- 日落固定在每天時間清單第一行。
- 營業時間、活動日期都要上網查最新資料，查不到就寫「以官網為準」。

## 五、發布

```
cd hokkaido-trip
python3 template/make.py template/trips/<代號>        # 依 trip.json 的 publish_path 輸出
python3 template/verify.py <publish_path>/index.html
git add -A && git commit -m "..." && git push origin HEAD:main
```
GitHub Pages 約 1–10 分鐘更新。每次建置 `sw.js` 版本會自動換，手機開網頁就會拿到新版。
